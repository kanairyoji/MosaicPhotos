キャッシュ実装詳細

プリミティブ（メモリ層・ディスク I/O）とディスク予算は ImageCacheKit に共通化し、「古い順に捨てる」手段は各キャッシュが持つ。ここでは命名規則・無効化・予算による追い出しの実装まで踏み込む。

プリミティブ: DiskImageStore

FileManager を薄く包んだだけの I/O 層。破棄ポリシー（LRU）は持たず、LRU 列挙の材料だけ提供する。コアは Foundation のみ（macOS テスト可）、UIImage 便宜は #if canImport(UIKit)。

API役割
data(forName:) / write(_:name:) / remove(name:) / clear()基本 I/O
touch(name:date:)disk hit 時に mtime を更新（mtime ベース LRU 用）
entries()各ファイルの (name, size, mtime) を列挙
totalUsage()合計バイト数

ディスクは 1 つの予算を全キャッシュで分け合う（ADR-185）

キャッシュごとの上限は持たない。予算（既定＝端末の総容量の 10%）を 4 つの参加者が共有し、超えたぶんだけ協調役が「どこから何バイト捨てるか」を決める。各キャッシュは自分の LRU で捨てる手段（budgetEvict(bytes:)）だけを実装する。

  • 層の合計がその層の床を割ったら次の層へ。同じ層の中では最後に触った時刻が最も古いキャッシュから chunkBytes（64MB）ずつ。1 手ごとに状態を取り直す（CacheBudgetPlanner.nextStep＝純関数・テスト対象）。
  • 判定はまとめて行う。各キャッシュは書き込み後に noteGrowth() を呼ぶだけで、協調役が数秒後に 1 回だけ合計を見る（旧実装は書き込みのたびに Dropbox の全行 fetch＝6.8 万行を舐めていた）。
  • 空き容量が 2GB を切る手前で予算を縮める安全弁つき（effectiveBytes）。極端に小さい端末でも下限 500MB は使う。
なぜ「キャッシュごとの上限」をやめたか（ADR-184/185） 上限が別々だと、片方が余っていても片方だけが溢れる。しかも上限はユーザーが枚数を見て決められる値ではない（端末サムネは 8 万枚で数 GB、本体画像は 1 枚数 MB）。枚数もユーザーも見ない規則——「1 つの予算・価値の低い順に捨てる」——にすると、ライブラリが育っても設定を変えずに済む。捨てられたものは次に見たときに取り直すだけで、機能は落ちない。

Dropbox キャッシュの構造

メタデータは SwiftData、バイナリは ImageCacheKit。保存先は Caches/DropboxKit/{thumbnails,fullimages}/。

ファイル命名（DropboxCacheNaming）

  • ファイル名 = SHA256(path) の 16 進 + 拡張子。
  • サムネイルは常に .jpg、本体は元拡張子（無ければ bin）。
  • 純ロジックなので actor から分離してテスト可能。

無効化（contentHash）

Dropbox が返す contentHash がキャッシュ済みと異なれば、その path のサムネ/本体を無効化して次アクセスで再取得する。

Dropbox 側の追い出し

DropboxCacheStore+Eviction が CacheUsageEntry を最終アクセス昇順に並べ、協調役から渡されたバイト数ぶんを古い方から削除する（本体画像は先読みしただけのもの → 閲覧済みの順）。種別ごとのバイト上限は安全弁として残っているだけで、通常の追い出しは予算が決める（DropboxCacheSettingsKeys の旧上限キーは未使用）。使用量は初回だけ台帳を集計し、以後は増減で追う。

メモリ層

MemoryImageCache は NSCache ラッパー。disk より前段で当たればディスク I/O を避ける。上限（totalCostLimit）は固定値ではなく端末のメモリ予算から算出する（MosaicSupport.MemoryBudget＝os_proc_available_memory() の約 5% を 60〜192MB にクランプ）——固定値だと低 RAM 機で jetsam、高 RAM 機で取りこぼし（ディスク再デコードの storm）になるため。圧迫時は MemoryPressureMonitor に登録した解放ハンドラで warning＝上限半減（LRU で縮小）、critical＝全消去。ただしサムネのキャッシュだけは purgeOnCritical: false で全消去せず段階縮小に留める（全部消すとディスク再デコードが一斉に走る）。
