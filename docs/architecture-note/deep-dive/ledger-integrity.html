台帳の守り方（ユーザーの表明）

このアプリのデータは 2 種類しかない——作り直せるもの（タグ・埋め込み・サムネ・クラスタの重心）と、二度と作れないもの（人物に付けた名前、束ね、ピープルグループの所属、「はい／いいえ」の答え）。後者をユーザーの表明と呼び、別の規律で扱う。このページはその規律をまとめる。

なぜ別扱いが必要か 作り直せるものは、壊れたら捨てて作り直せばよい——起動を止めないことが最優先。 いっぽう表明は利用者の時間そのもので、消えたら復元できない。 それなのに、表明は「作り直せるもの」と同じテーブル・同じ遷移の中に居る （名前は PersonCluster の列で、クラスタは夜ごとに作り直される）。 だから「全部捨てて作り直す」操作のたびに、表明だけを意識して救い出す必要がある。

1. 壊れたときの方針を型で分ける（ADR-186）

resilientModelContainer(name:schema:policy:) は、開けなかったときの振る舞いを 方針で切り替える。

方針対象開けなかったら
.rebuildableAutoAlbumV10・TagsV1・DropboxCache・UsageV1ストアファイル（.store/-wal/-shm）を削除して作り直す。再解析で回復する
.ledgerFacesV1・BackupKit⚠️ 削除しない。開く前に控え（StoreSnapshot）を取っておき、失敗したら控えから戻して 1 回だけ開き直す。なお駄目ならインメモリで起動だけ通す

⚠️ スキーマの進め方も違う。作り直せるストアは名前を採番して旧ストアを捨ててよい （現行 "AutoAlbumV10"）。台帳は採番しない——optional 列の追加と テーブルの追加だけで進める。コンテナ名 "FacesV1" は固定。

2. 表明とは何か（一覧）

「これはユーザーが決めたことか」を 1 か所で判定する（FaceStore.isUserClaimed）。 散らすと必ず 1 か所抜ける。

  • 名前（PersonCluster.name）
  • 束ね（personGroupID・ADR-61。成長した子供を 1 人として扱う）
  • ピープルグループの所属（PeopleGroupRecord.memberClusterIDs・ADR-231） — ⚠️ 無名でもグループに入れていれば表明。枚数フロアも免除する （1 枚でも表示／0 枚でもグループメンバーなら表示）
  • 確認済みの顔（confirmedAt）と修正（FaceCorrection・負例を埋め込みで永続化）
  • 代表写真の指定（coverFaceID） — ⚠️ これだけは全体の再スキャンを跨げない（顔 ID が変わるため。既知の制約）

3. 全消去して作り直すときは、表明を持ち越す（ADR-232）

モデル世代の切り替え・パイプライン版の更新・手動の再スキャンでは、顔もクラスタも全部消える。 このとき名前だけを持ち越していた時期があり、束ねとグループ所属が黙って失われていた。

  • 持ち越しは CarriedAssertion（名前／personGroupID／所属グループ／代表的な写真キー）に まとめ、写真の重なりで新しいクラスタへ割り当て直す。
  • ⚠️ 束ねのタグは番号を振り直す。旧世代の personGroupID をそのまま使うと、 新世代で同じ番号を割り当てられた別人と合流する。衝突しない負の番号を台帳から採る。
  • ⚠️ 上限に当たったら「いま」を残す。持ち越しの件数に上限を置いたとき、 控えより先に保留分を並べたため溢れたときに現在の表明が落ちていた（レビューで発見）。 順序は snapshot + pending。
  • ⚠️ 世代を切り替える前に、保留中の持ち越しを混ぜる。promoteShadow が 持ち越しを上書き・削除していた。

reset() はグループのメンバーを空にする（clusterID は意味を失うため）。 ⚠️ 行そのものは消さない——グループの id と名前はユーザーが付けたもの。 空にしてから持ち越しに入れ直させる。

4. 「読めなかった」を「1 つも無い」と読まない（ADR-242）

⚠️ 同じ形を 3 回踏んだ

countedFetchOptional は fetch の失敗で nil を返す。 これを ?? [] で畳んだ値を「もう居ない」の根拠にして消すと、 読めなかった瞬間に全部消すことになる。しかも消したあとは表示も監査も静かになるので 誰も気づけない。

  • peopleGroupMemberClusterIDs() — 失敗を「グループ無し」としてキャッシュしていた
  • pruneStaleGroupMembers() — 家族グループのメンバーが全消え＋save
  • repairOrphanFaces() — ライブラリ全体の顔が未割当へ戻る（直す関数が一番大きく壊す）

規律: 消す・戻す・上書きする判断に、失敗を畳むヘルパを使わない。 nil なら何もせずに見送って記録に残す。 ヘルパ（allClusters()）の宣言にもそう書く——次に書く人が見るのは ADR ではなく宣言。

⚠️ 0 件の扱いは一律にしない。分かれ目は「失うものが戻せるか」: 掃除は 0 件も見送る（世代切り替え直後は本当に空で、そこで落とすと持ち越しが埋める前に失う）。 孤児の修復は 0 件でも走る（0 件が直すべき状態そのもので、再クラスタで作り直せる）。

5. 表明の国勢調査（ADR-233/235）

「失っていないこと」を遷移の前後で数えて突き合わせる。 AssertionCensus は純ロジックで、人物ごとの (名前・束ね・代表の有無・確認顔の数・写真キー) と グループを数える。

  • 遷移（rebuild / rescan / promote / prune）の前後で diff を取り、減っていたら種類ごとにまとめて診断ログへ出す。
  • ⚠️ 何も減っていなくても 1 行は出す。「出ていない」と「そもそも走っていない」を 区別できないログは後から役に立たない。
  • ⚠️ 再スキャン中は言わない。持ち越しが進行中は「まだ戻っていない」だけで、 それを「失った」と呼ぶと毎晩誤報になる。
  • ⚠️ 戻らない記録は掃除する（pruneStaleGroupMembers）。 ADR-231/232 は「これから失われる」のを防ぐもので、既に失われた分は直さない。 放っておくと表示が永久に 1 人足りず、監査も毎回それを報告して 256KB のログを埋める。

6. 遷移が来なくても分かるようにする（ADR-238）

⚠️ 国勢調査は遷移のときだけ出る。ところが解析が終わった端末では夜間の再クラスタの条件が 何週間も満たされない（実機ログで 13.5 時間に 0 回）。 つまり「壊れたら勝手に分かる」は「壊れる機会があったときに分かる」でしかなかった。

そこで reportLedgerHealth() を起動ごとに 1 回出す。

faces: ledger clusters=… named=… bundles=… covers=… groups=… groupMembers=N/M stale=K

⚠️ 顔は読まない（全顔の走査は実機で 4.5〜9 秒）。クラスタ行とグループ行だけで数えられるものに絞る。 stale=K が増えていくなら記録が壊れている。

7. 実機の台帳を Mac で回す（ADR-234）

遷移の検証は数晩の再解析と、本物の名前・グループを賭けるので実機では試せない。 だから台帳を持ち出して Mac で再演する。

  • 控え（takeManualSnapshot）— 再スキャンを試す前に押しておけば数分で戻せる。 ⚠️ 戻したらアプリを終了して開き直す（SwiftData がストアを掴んだままなので、 そのまま使うと書き戻しで壊し得る）。画面にも「要・再起動」を出す。
  • 書き出し（exportForReplay(redacted:)）→ Mac で FACE_LEDGER_DIR=… swift test --filter FaceLedgerReplayTests。
  • ⚠️ 本名とパスを外す（FaceLedgerRedaction・塩つき SHA256）。 refKey と faceID は同じ置き換えで作り直す（faceID は <refKey>#<連番> なので 片方だけ変えるとパスが faceID 側から漏れ、参照も壊れる）。
  • ⚠️ 台帳にモデルを足したら、匿名化にも行を足す。 FaceScanAttempt（refKey を持つ）を足した直後、匿名化の対象から漏れていた。 バイト検査は前から在ったのに通っていた——fixture にその行が無いので当然見つからない。 いまは scripts/check_forbidden_patterns.py が 「人を指す文字列（refKey/faceID/coverFaceID/name）を持つ台帳モデルは匿名化されていること」を CI で検査する。
  • ⚠️ -wal まで見る。匿名化は本体の行を書き換えるが、 書き換える前のページは -wal に残り得る。 匿名化のあとに wal_checkpoint(TRUNCATE) で畳み、畳めなければ失敗として返す ——「たぶん大丈夫」で個人情報入りのファイルを渡さない。
  • ⚠️ 外しても顔の特徴量は入ったまま。使い終わったらフォルダごと消す （.gitignore がコミットは弾く）。
