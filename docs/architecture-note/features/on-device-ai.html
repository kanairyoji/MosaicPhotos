オンデバイス AI

固定の語彙リストや OCR を持たず、任意言語の自然文で AI アルバム／意味検索を行う。実装は「タグ台帳＋LLM 審査」の多層構成（ADR-23/24）：シーンタグ・CLIP 埋め込みを夜間に付与し、検索は決定的ハード条件＋タグ一致＋CLIP 対比＋字句の RRF 融合＋証拠ゲート＋LLM 審査で決める。通信なし・API キー不要。モデルと検索品質はすべて実測で決める（records/model-evaluations.md）。

索引（夜間パイプライン）と検索

索引は夜間バッチ（電源＋Wi-Fi＋アプリ非使用の BGProcessingTask・実行タイミング参照）で、新しい写真から先に（撮影日降順・ADR-36）次の順に付与する。

  1. Vision シーンタグ（OS 内蔵 VNClassifyImageRequest・約 1,300 クラス・hasMinimumRecall(forPrecision:) の校正済み足切り＝自前閾値が消える）— 全写真
  2. CLIP 埋め込み（OpenCLIP ViT-B-32・INT8 量子化・意味検索の索引）— 全写真
  3. ※ 旧・第 3 段の VLM キャプション（SmolVLM-500M）は機能ごと廃止（ADR-108）。網羅率アブレーションで検索寄与ゼロ（Δ F1 = 0.0001）と計測され、モデル 877MB を削除した。

なぜ「閾値レス」へ再設計したか（ADR-24） 以前は生 CLIP コサイン＋絶対閾値だったが、ユーザーのライブラリ分布が事前に不明で閾値を調整できず「除外が 97% を落とす」「意味採用 0 件」が起きた。そこでタグ一致（離散・閾値レス）を第 3 のランキングに加え、除外は肯定/否定ベクトルの相対判定（絶対閾値なし）にし、最終判断をLLM 審査（言語判定）に委ねた。判定根拠がタグで可視化されデバッグ可能になる。
解釈は「作成時に 1 回だけ」＋言い換えプローブ（ADR-23・ADR-35） 検索文→QuerySpec・英訳・言い換えプローブ（最大 4）の LLM 解釈はアルバム作成/編集時に 1 回だけ実行して AIAlbumInterpretationStore（JSONFileStore・版管理）へ永続化する。起動時・写真追加時に LLM は走らない。意味採点は主フレーズ＋プローブの max-over-probes＝言い換え表現の取りこぼしを回収（ハーネス実測で言い換え再現率 +17〜18pt）。ただし除外つきアルバムではプローブを対比に使わない（肯定の最大値が底上げされ除外が素通りする回帰の防止）。再評価は増分（新規埋め込み分だけ採点）＋ドリフト検知のフル再評価。

量子化の非対称性（学び） 出力が連続ベクトルの部品（CLIP や VLM の視覚エンコーダ）は INT8 に強い（fp16 と cos≈0.999）。一方 LLM デコーダは弱い（次単語 argmax が反転・fp16 と一致 26%）。よって CLIP は全体を INT8 にしている（当時同梱していた VLM は視覚のみ INT8・デコーダ fp16 とした。VLM 自体は ADR-108 で廃止）。また Core ML の正しさは Mac だけでは検証できない——Florence は Mac の全 compute unit で正常でも実機 fp16 で破綻した。新モデルは実機ログ（生成 ID・有限性）で確認してから採用する。

検索の融合（RRF）と証拠ゲート・審査

検索は 4 層。決定的なハード条件で絞り、複数のランキングを Reciprocal Rank Fusion で束ね、除外つきは証拠を要求し、最後に LLM が言語で判定する。

  • P0 接地: 日付は RelativeDateParser（日英）を唯一の出典・場所はカタログ/原文出現に接地・人物名は顔クラスタへ接地（PersonNameGrounder＝「太郎」→山田太郎・姓名の部分指定対応）。人物条件の評価は焼き込みでなく現在のクラスタ名でライブ照合（改名/統合が即反映）。QuerySpecSanitizer がプレースホルダ除去・include/exclude 衝突解消。
  • P1 融合: Vision シーンタグ一致（離散・閾値レス）＋CLIP 対比（max-over-probes・除外は相対判定のみ）＋LexicalSearch（地名/人物）を AIAlbumSearcher が RRF 融合。除外語はタグの離散一致でもハード除外。
  • P2 証拠ゲート＋審査: 除外つきは条件に答えられるチャネルの証拠を必須にする（タグ／顔実測／人数実測。人物除外なら人物について語れる証拠を要求＝ADR-100）。そのうえで AlbumVerifier（Foundation Models）が keep/drop/unsure 判定。unsure は最大 2 回の再判定で多数決。空振り時はプローブ語を生成して 1 回だけ再検索（Refine）。
検索品質はクエリ集ハーネスで数値管理（ADR-104） 判断はデータセット計測で行う（体感・個別事例では決めない）。正本の台帳は records/search-quality.md。ハーネスは 2 本——SearchEvalTests（COCO val2017 ラベル・macOS・解釈→接地→照合→証拠ゲートの層）と SearchEvalCaltechTests（Caltech-101・広い語の接地込み）。現行値は COCO 116 本マクロ P=1.000 / R=0.833 / F1=0.896、Caltech（接地込み）F1=0.860。カテゴリ別 F1 の下限（現状値−0.03）と全体 precision≥0.97 を SearchEvalRegressionTests の回帰フロアとして常設し、黙った劣化が入ったら落ちるようにしている。認識力込みの評価は SearchQualityTests（Imagenette 200 枚＋28 クエリ・実パイプライン）が担う。

作成 UI の入力支援（ADR-37）

コンポーザーは本番検索と同じ決定的レイヤーで入力を支援する（＝プレビューが実際とズレない）。(1) サジェストチップ＝ライブラリから観測された語（命名済み人物・カタログ実在の地名・頻出タグ∩レキシコンの日本語・日付定型）をタップで挿入——確実にヒットする語だけを出す。(2) 接地プレビュー＝入力がどう解釈されたか（人物/場所/視覚語/日付）を色付きチップで表示。(3) ハード条件のヒット件数をライブ表示（0 件は作る前に分かる）。基盤はライブラリスナップショット（5 分キャッシュ）＋350ms debounce。

ピープル（顔クラスタ）

写真アプリの「ピープル」は公開 PhotoKit API でアクセスできない（旧 subtype-1000 方式は常に空だったため撤去）。代わりに Vision 顔検出＋同梱顔モデル（AuraFace-v1・512 次元 L2 正規化）で identity 埋め込み→逐次クラスタリングで自前の「人物」を作る。ロジックは独立パッケージ FaceCore（FaceClustering 純・FaceStore は別コンテナ "FacesV1"・PeopleEngine ファサード・純ロジック各種）。CLIP と共有する下層（ベクトル演算・写真キー・背景トリクル・ANE ゲート）は PerceptionCore にある。対象は端末＋クラウド（Dropbox）両方（ADR-33）：端末は 1024px（旧 640px）、クラウドはキャッシュ済みサムネイル（追加DL なし）。長押しメニューから改名・代表写真・顔の付け替え・別の人物と束ねる。命名した人物は AI アルバムの人物条件に接地し、照合はライブ（改名/束ねが即反映）。顔モデル未同梱ならセクション非表示。

精度は「候補→データセット計測→採否」の反復で作った（FaceAccuracyEvalTests／FaceEvalMetrics・台帳 face-accuracy.md・FG-NET/LFW）。効いた変更だけを採用し、直感に反して悪化した案（外れ値除去・年齢分類・自動細分割の 2 階層）は計測で棄却した。

  • 不確かな顔を弾く多段ゲート（ADR-48/52/53）: 検出信頼度・クロップ再検証（二段検出）・ぼけ（ラプラシアン分散）・露出（平均輝度）・絶対 48px／正規化サイズ比・顔向き（yaw/roll）・目閉じで品質を減衰し、フロア 0.40 未満はクラスタに入れない。偽陽性は顔なし画像で 0%。
  • 埋め込みの安定化（ADR-51/54）: 両目ランドマークでアライメント＋マルチクロップ平均＋EXIF 回転の正規化。
  • クラスタリング（ADR-56〜58・ADR-68/70）: しきい値・マージン等の定数はモデルの類似度分布に張り付くため FaceTuning のプロファイルに集約し、同梱モデルの宣言で選ぶ。現行 v5（AuraFace）は既定しきい値 0.35（校正の可動域 0.25〜0.40）＋マージンゲート 0.04（1 位/2 位の差が小さい紛らわしい顔は入れない）＋サイズ適応マージン（最大 0.08・小/新クラスタほど厳しく）＋同一写真 cannot-link＋共起 notSame。FG-NET 全体で B-Cubed F1 0.790 / 分裂 2.8（facenet 最良は 0.664 / 3.7）、家族シナリオ（LFW 3〜5 人）は F1 1.000・分裂 1.0。
  • ユーザー修正から学習（ADR-45/46）: 品質重み・負例エグゼンプラ（埋め込みキーで再スキャン跨ぎ）・確認済み顔アンカー・しきい値校正。「同じ人物ですか？」レビューで判断が割れるケースだけ尋ねる。パイプライン版を上げると全再スキャンし、命名は写真の重なりで持ち越す（ADR-51）。
  • 2 階層の人物束ね（ADR-61）: 成長で複数クラスタに分かれた子供を 1 人物として束ねる（personGroupID・融合せず純度を保つ・後で解除可）。子供は撮影日（≒年齢）で時期グループ・大人は融合。「束ねる＝子供」なので年齢推定 API も追加の判定モデルも要らない。表示・検索・名前・顔ハイライトは束ねを反映。純ロジックは FacePersonGrouping。子供の成長を跨ぐ識別が計測で +3.8pt、大人は融合維持で 99.1%。
  • 顔ハイライト: 人物アルバムの「顔を表示」トグルで、認識した顔（束ねた全時期）をサムネ／全画面に黄枠表示（faceHighlightProvider／FaceBoxMapping・PhotoSourceKit は AutoAlbumCore 非依存を維持）。
顔と CLIP は Neural Engine を奪い合う（ADR-70/73） Vision の顔検出（perform）と Core ML の CLIP 推論・モデルロードが同時に ANE を使うと実機でデッドロックし、顔スキャンが最初の 1 枚で固まる障害があった。以前は CLIP 埋め込みが回線ゲートで止まっていて顔スキャンが ANE を独占できていたため顕在化していなかった。現在は MLInferenceGate で同時に 1 つだけに直列化し、ゲートは「ANE に触れる場所」の内側で取る。詳細は 並行・バックグラウンド処理。

表示タグは検索と同じ台帳

フル画像に出すキーワードタグは Vision シーンタグ（TagStore・検索の一次ランキングと同一ソース）を第一に、CLIPDisplayLabeler（約 300 語ゼロショット・保存済み埋め込み使用）で補完する。シーンタグは 1 回の Vision 一括パスで OCR（写真内テキスト）・動物種別・人数・美的スコア・アセット種別（スクショ/パノラマ/Live Photo 等）も同時取得し（ADR-47）、OCR は字句検索の一チャネル・美的スコアはカバー選択・種別はタグ検索に使う。フル画像の情報パネルには「写真内のテキスト」欄・利用カウンタ（閲覧/共有回数）も出る（ADR-49）。顔の数・スクリーンショット判定・解析状態も同パネルに出す。※ 旧「AI description」欄（VLM キャプション）は ADR-108 で廃止した（PhotoTagRecord.caption フィールドは TagsV1 のスキーマ互換のため残置・新規は常に nil）。進捗はユーザー向けの「AI 解析の状況」（パス別進捗・最終実行時刻・今すぐ解析）で可視化する。

背景処理のスロットリング

シーンタグ・CLIP 埋め込み・顔スキャンは BackgroundTrickle の骨格で小バッチ＋バッチ間スリープ＋.background QoS で trickle 実行する。重さは設定（段階）で調整でき、停止判定は 1 枚単位（ADR-25）。ユーザー操作中・メモリ圧迫中・クラウド取得中は処理を譲る。シミュレータでは背景推論を実行しない。モデルは critical のメモリ圧迫で解放し、次回利用時に再ロードする。詳細は バックグラウンドと省電力。
