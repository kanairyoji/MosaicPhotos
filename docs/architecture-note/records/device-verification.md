# 実機で確かめること（ADR-195〜199 ＋ レビュー 9 周）

> **なぜこの一覧があるか**
> ADR-195 以降の変更は**一度も実機で動かしていない**。ビルドとテストは通っているが、
> 変わったのは「OS の処理枠」「回線ポリシー」「継続タスクの表示」「共有相手とのやり取り」など、
> **シミュレータでもユニットテストでも確かめられない**ものが中心になっている。
>
> 片付いた項目は行ごと消さず「確認: 済（日付・結果）」を追記する。
> 問題が出たら `case-studies.md` / `unresolved-problems.md` へ移す。

## C. 共有写真の撮影日（ADR-199 ＋ レビュー 1〜8 周目）

⚠️ **2 台要る**（送信側・受信側）。片方だけでは確かめられない。

| # | 何を確かめるか | 手順 | 期待 |
|---|---|---|---|
| C1 | 送信側が撮影日を載せる | 送信側を更新 → 共有を反映 | 診断ログに `analysis shards +N`。解析データが上がり直す |
| C2 | **受信側の 1 回だけの取り直し** | 受信側を更新 → 取り込み | 診断ログに `receiver capability 1 → 2 — re-fetching all analysis data once`。**1 回だけ**出る（毎回出たら異常） |
| C3 | 取り直しの分割 | C2 の後、何度か取り込む | 1 回あたり最大 48 シャード。回を重ねて全部揃う（メモリ警告やクラッシュが出ないこと） |
| C4 | **受信した共有アルバムの並び** | 受信側で共有アルバムを開く | 撮影日の昇順（下が新しい）。アップロード順でない |
| C5 | **月の見出し** | C4 でスクロールして見出しを見る | 撮影日に基づく月（反映した日付でない） |
| C6 | 開いたままの反映 | 共有アルバムを開いたまま取り込みを走らせる | ⚠️ **既知の未解決**。閉じて開き直すまで古い並びのままの見込み。実際にそうなるか確認する |
| C7 | 全画面での並び替え | ホーム（All Photos）で写真を全画面表示したまま取り込みを走らせる | ⚠️ **既知の未解決**（レビュー 8/9 周目）。ラベルと中身が食い違う見込み。実際に起きるか確認する |
| C8 | 取り込み中の前面復帰 | 取り込み中にアプリを行き来する | 記録が壊れない。次回の取り込みで続きから進む |
| C9 | 撮影日の訂正 | 送信側で写真の撮影日を直して再反映 | 受信側で日付が更新される（古い値が残らない） |

## 見るべき診断ログ

Developer Options → 診断ログ。目印になる行:

- `analyze:` — 解析セッションの開始・停止・理由
- `share import: capture dates — +N, total M, overCap X, evicted Y, saveFailed Z`
- `ShareAnalysisFetch: receiver capability 1 → 2`（**1 回だけ**）
- `ShareAnalysisFetch: download failed` / `invalid analysis data`（区別されていること）
- `merged.rebuild: local=… cloud=… total=… sort=…ms`
- `embed: batch` / `embed: skipped — already running`
