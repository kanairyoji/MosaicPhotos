データセット評価と意思決定

検出性能（AI アルバム検索・顔クラスタリング）に関わる変更は、体感や個別事例では決めず、正解ラベル付きデータセットの計測で決める（ADR-104）。この章は「どのデータセットを何のために使い、どの判断がどの計測で決まったか」をまとめる。指標（Precision / Recall / F1 / マクロ平均…）の一般的な定義は AI 基礎 9. 評価指標と実験設計 を参照。

なぜ「体感で決めない」を規律にしたか 検索の不具合報告は常に個別事例で届く（「この検索に変な写真が混ざる」）。個別に直すと 点対応が積み上がり、別のクエリを黙って壊す。逆にデータセットがあれば、 (1) 弱点がカテゴリ単位で数値特定でき、(2) 対策の効果が Δ で出て、 (3) 副作用（他カテゴリの劣化）が同時に見える。実際、この方式に変えてから 「偽陽性の内訳を数えたら真犯人はレキシコンの最長一致だった」（タグ照合は無実）のような 誤った仮説の棄却が何度も起きている。

使用データセット一覧

データセット規模何を測るか選んだ理由
COCO val20174,952 枚・80 クラスの物体ラベル検索パイプライン全体の precision / recall / F1（SearchEvalTests・123 クエリ・10 カテゴリ）「写真に何が写っているか」の人手ラベルが正確で、除外クエリ（〜が写っていない）の正解集合を機械導出できる。家庭写真に近い被写体分布（人・犬・食べ物・乗り物）
Caltech-101101 クラス・約 9k 枚語彙接地の end-to-end（SearchEvalCaltechTests / CentroidGroundingEvalTests）：「食べ物」「動物」等の広い語が正しい下位クラスへ展開されるかクラスが上位概念でまとめやすい（楽器・乗り物・昆虫…）ため、「広い語 → 下位概念」の正解を保守的に人手定義できる。重心フィクスチャは同梱と同じ Core ML モデルで生成
FG-NET82 人・年齢横断の顔顔クラスタリングの混入率・分割度（FaceAccuracyEvalTests）同一人物の年齢変化を含む数少ない公開セット＝家庭ライブラリ最大の難所（子供の成長）を直接測れる
LFW5,749 人・13k 枚顔識別の一般精度・しきい値校正の妥当性顔認識の標準ベンチ。人数が多く「別人を混ぜない」側の統計が取れる
Imagenette（歴史）10 クラス・200 枚抽出初代検索ハーネス（28 クエリ・Recall@k）最初の弱点特定（言い換えの取りこぼし）に使用。COCO ハーネスへ発展的に置き換え

データセットは scripts/fetch_search_eval_datasets.sh で取得し、.search_eval/（gitignore 対象）に置く。無い環境では評価テストは安全にスキップされる（CI を壊さない）。

評価環境の要件（結果を信用できる条件）

  • 本番と同じコード経路 — ハーネスは previewInterpretation → searchWithPool → 証拠ゲート という実装そのものを呼ぶ（テスト専用の近道を作らない）。
  • 実機の索引網羅率を再現 — 合成コーパスはタグ 86%・顔 11% という実機の網羅率の偏りを決定的乱数で再現する。これが無いと「未索引を『無い』と読む」型のバグ（除外の最大の敵）を見逃す。シーンタグは場面分類であって物体検出ではない現実（人が写っていても person タグが出ない）も再現する。
  • 決定的 — サンプリングは refKey からのハッシュで決め、再実行で同じ数字になる。
  • 正解 0 件のクエリを含む — 存在しない被写体（恐竜・ユニコーン）は 0 件を返すのが正解（P=R=1 の採点規則）。「無いものに答えたふりをしない」を計測で保証する。

クエリ集（COCO・123 本・10 カテゴリ）

カテゴリ本数例見ているもの
subject（被写体）50「犬の写真」基本の当たり
exclusion（除外）14「人が写っていない写真」証拠主義・混入ゼロ（実障害の主戦場）
conjunction（複合）12「犬が写っていない猫の写真」肯定×否定の組み合わせ
compound（人物×内容）7「太郎の犬の写真」「太郎の写真」AND の構造保証（人物名の二重計上で OR 化した実障害の再発防止）。コーパスに命名済み人物を決定的合成
date / count / attribute8+4+8「2024年の犬」「2人の写真」「笑っている写真」日付・人数・属性（実測シグナル）の複合
phrase / en / robust7+6+4「犬の写真を探して」"photos without dogs"言い回しの揺れ・英語直入力に不変であること
specificity（特異性）3「恐竜の写真」存在しない被写体に 0 件を返す

現状値（2026-08）：マクロ P=1.000 / R=0.837 / F1=0.899。カテゴリ別 F1 の回帰フロア（現状値 −0.03）と全体 precision ≥ 0.97 を SearchEvalRegressionTests が固定する。

この計測で決めた判断（実例）

判断計測結果
語彙接地は「語同士」でなく「タグ重心」（ADR-101）Caltech-101 で両方式の F1 比較text↔text は接地 3/10・F1 0.300（Precision 1.0 に見えるのは諦めているだけ）。重心（text↔image）は 10/10・F1 0.86 → 採用。回帰の固定として「重心版が語彙版に負けたら落ちる」テストを常設
広い語の採用規則＝凝集した高原（ADR-102）パラメータ掃引（peak×plateau の 9 組）＋雑音語の負例animal 型（該当語彙が多く突出しない）は凝集度 z≥2.0 で雑音語と完全分離。F1 0.746→0.902
凝集精錬はゲートつきでだけ適用（ADR-105）COCO/Caltech 両ハーネス無条件適用は不均質な正解群（乗り物）を壊す（F1 0.4→0.25）。グループ凝集 z≥1.0 のときだけ適用で bird 0.833→0.909・food 0.667→0.800
VLM キャプションの廃止（ADR-108）網羅率アブレーション（0% / 実機 1% / 理想 100%）Δ(1%−0%) F1 = 0.0001＝寄与ゼロ。100% でも +0.008（到達に夜間窓 30 日分）→ 機能ごと廃止（−877MB）。廃止後の再計測で F1 不変を確認
人物×内容の AND 保証（ADR-109）compound カテゴリ新設（命名済み人物を合成）実効内容語の導入で P=1.000（混入ゼロ）。フロア 0.91 を常設
除外の証拠は humanCount を主軸に（ADR-100）COCO 除外クエリ「未計測 ?? 0」を禁止し実測必須に：「人が写っていない」P 0.490（誤混入 2,062 枚）→ 1.000
レキシコンの最長一致・単語境界（S5）COCO・偽陽性の内訳分析「電車」が車にも当たり 502 枚混入（train P 0.214）→ 最長一致＋占有で 1.000。"dog"⊂"hot dog" も単一語＝タグ全体一致で解消
顔クラスタの各ゲート・しきい値（ADR-48〜58）FG-NET / LFW（FaceEvalMetrics）マージンゲート・サイズ適応・アライメント等を 1 つずつ計測して採否。混入率 58%→12%。直感に良さそうな案（重心からの外れ値除去）は成長データで悪化し棄却
言い換えプローブ（max-over-probes）（ADR-35）初代 Imagenette ハーネスの A/B言い換え再現率 +17〜18pt を確認して採用（除外クエリではプローブ無効＝副作用も同時に計測）

実例詳報：VLM キャプション廃止の計測データ（ADR-108）

「検出への貢献」と「処理の重さ」を突き合わせて機能を落とした実例。判断に使った 2 つの表をそのまま載せる（正本は search-quality.md §S13・2026-08）。

1. AI 系機能の「重さ × 検出への貢献」棚卸し

機能処理の重さ（実測）検出への貢献根拠
Vision シーンタグ軽い（数百 ms/枚・OS 内蔵）大きい検索の一次ランキングそのもの
humanCount（人数実測）軽い（タグ付けと同一パスで無償）大きい「人の写っていない」除外 P 0.490 → 1.000
CLIP 埋め込み中（推論 10〜30ms・壁時計 1.6s/枚）大きい意味検索の対比＋語彙接地の重心の原料（接地 F1 0.86 の土台）
美的スコア軽い（タグ付けと同一パス）中「綺麗な写真」条件・カバー選択
顔スキャン重い（約 0.8s/枚・うち 0.7s は画像ロード）中笑顔・人物名条件＋ピープル機能の本体（検索以外の価値大）
FM 解釈・審査作成時 1 回のみ（数秒〜十数秒）中自然文→条件の入口。常時コストなし
VLM キャプション最重量（1 枚数十秒・モデル 877MB）ほぼない下のアブレーションで定量化 → 廃止

構図：貢献の大きい 3 つはすべて軽く、最も重い 1 つだけが貢献ほぼゼロ——重さと貢献が逆転しているのはキャプションだけだった。前提の確認として、キャプションは検索の順位付け（タグ一致・CLIP・字句・RRF）に元々不参加で、役割は「証拠ゲートの存在 1 票」「LLM 審査の文脈」「情報パネル表示」の 3 つのみ。

2. 網羅率アブレーション（COCO 116 クエリ・当時）

キャプション網羅率を 0%（廃止相当）／1%（実機の実測値）／100%（理想上限）に振り、他の条件（タグ 86%・顔 11%）を固定して全クエリを再計測した：

キャプション網羅率全体 P全体 R全体 F1除外つき P除外つき R
0%（廃止相当）1.0000.8330.8960.9990.870
1%（実機の現状）1.0000.8330.8960.9990.871
100%（理想上限）0.9990.8500.9040.9950.941
  • Δ(1% − 0%) F1 = 0.0001 ＝ 実機の網羅率では検出性能への寄与は事実上ゼロ（廃止しても数字が動かない）。
  • 100% なら除外 R +0.071 だが、86k 枚 × 数十秒 ≈ 夜間窓 30 日分以上＝到達不能。同じ証拠役は humanCount（86%・無償）が既に果たしていた。
  • 実機ログの裏付け：全セッションで caption.photoMs のサンプルがゼロ（顔スキャンに夜間窓を奪われ、キャプションは構造的に一度も回っていなかった）。「最重量なのに動いてすらいない」が現状だった。
  • 廃止後の全ハーネス再計測で COCO マクロ P=1.000 / R=0.833 / F1=0.896 ＝廃止前と同値・回帰フロア全通過を確認してから削除した（アプリ −877MB）。
この計測の設計ポイント 「使われている場所が少ない」ではなく「外したら数字がどう動くか」で判断した点。 機能の存在理由（証拠 1 票）はコード上は正当に見えたが、アブレーションは 「その 1 票が実際の判定を変えた回数」を暗黙に集計してくれる。逆に 100% の列は 「もし全力投入したら」の上限を示し、回収可能な伸びしろと必要コストの比まで 1 枚の表で判断できる。

運用（台帳と更新ルール）

  • 台帳が正本 — 検索は records/search-quality.md（S0〜S15 の段階別寄与）、顔は records/face-accuracy.md、モデル比較は records/model-evaluations.md。解釈・照合・接地・証拠まわりを変えたらハーネスを回して差分を台帳へ記す。
  • フロアの変更には理由を書く — 意図的なトレードオフでフロアを割る場合は、台帳に理由を記してからフロアを更新する。
  • ハーネス自体も進化させる — 実障害が起きたらまず「その型のクエリ」をカテゴリとして追加し（例：compound）、修正がフロアで恒久化されるようにする。
