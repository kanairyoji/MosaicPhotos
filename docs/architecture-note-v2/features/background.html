バックグラウンドと省電力・通信制御

シーンタグ付け・CLIP 埋め込み・顔スキャン・自動アルバム生成といった重い処理は、原則としてアプリを使っていない時間帯（画面ロック中の BGProcessingTask）にだけ動かし、フォアグラウンドでは原則走らせない（ADR-25）。実行条件は独立した 4 軸の設定（ADR-80）でユーザーが選べる。さらに一枚岩の重い保守（AI アルバムの本番化・全再評価・自動生成＝始まると途中で譲れない）は、前面アイドルでも動かさず非アクティブ（ロック・アプリ切替）限定の厳格ゲートに分離する（ADR-107・「使用中にいちいち固まる」実障害の修正）。状況は最上部のアクティビティバーで可視化する。

なぜ「使っていない時だけ」なのか（ADR-25） 旧ゲートは「電源＋低電力OFF＋アイドル 60 秒」だった。充電しながら閲覧中に 60 秒触らないと重い処理が走り出し、操作を再開してもクラウド写真のタグ付け（1 バッチ最大約 27 秒）が譲れず操作が固まった。そこでアイドル判定を廃止し、「電源＋低電力OFF＋アプリ非アクティブ（scenePhase）＋Wi-Fi」に変更。フォアグラウンドでは重い処理をゼロにした。停止判定も全処理1 枚単位に統一し、操作・遷移が来たら即譲る。

重い処理の実行条件（4 軸設定・ADR-80 / HeavyWorkTiming）

段階の梯子ではなく、独立した 4 つの設定の全条件を満たしたときだけ重い処理が動く（判定は純関数 HeavyWorkTiming.allows(...)）。低電力モード・メモリ圧迫はどの設定でも常にブロックする安全弁。

軸選択肢（太字＝既定）
1. 自動処理自動で解析する / オフ（手動「今すぐ処理」のみ）
2. 前面で動かすか（控えめ）ON＝アプリ使用中は動かさない / OFF＝20 秒操作が無ければトリクル系のみ動く（触ると即停止）
3. 電源充電中のみ / 常に / オフ
4. 回線Wi-Fi のみ / セルラーも / Wi-Fi かつ低データ以外 / オフ（通信を要しないローカル解析には課さない）

中央ゲートは BackgroundYield.heavyWorkAllowed（回線あり）と heavyWorkAllowedLocal（ローカル専用・Wi-Fi 条件なし）。一枚岩の保守は加えて monolithicHeavyWorkAllowed（非アクティブ限定・ADR-107）を通す。手動の「今すぐ処理」（30 分ブースト）は前面/回線条件を免除する（電源系の安全弁は維持）。BGTask 起動時は scenePhase 変化が来ないため冒頭で非アクティブを明示する。正本は records/background-behavior.md（どの設定で何が動くかの早見表・ゲートを変えたら必ず更新）。

AI アルバム作成は 2 段階（即時プレビュー→即時本番化）

作成時は決定的プレビュー（レキシコン＋日付＋タグ照合・LLM なし・1〜2 秒）で即座にメンバーを見せ、そのままその場で本番化（FM 解釈＋フル評価＋審査・十数秒・utility 優先度＝ユーザーの明示操作なので夜間ゲートの対象外・ADR-110）。語彙接地（重心）だけはキャッシュ済みのときのみ行い、コールドなら pendingFinalization を残して夜間の finalizePending（非アクティブ限定）が接地込みで仕上げる。

電源ゲート（PowerStateMonitor）

UIDevice.batteryState と ProcessInfo.isLowPowerModeEnabled を監視し、ポリシー BackgroundPowerPolicy（While charging=既定 / Always / Off）と合わせて backgroundAllowed() を返す。While charging は「電源接続（charging/full）かつ 低電力モード OFF」。

シミュレータ注意 シミュレータは充電状態を .unknown で返すため、charging/full のみで判定すると背景処理が全部止まる。「.unplugged と確定したとき以外は電源扱い」にしてロックを避ける。

回線ゲート（NetworkStateMonitor）

NWPathMonitor で isOnWiFi（Wi-Fi/有線）・isExpensive（従量）・isConstrained（低データモード）を監視し、ポリシー BackgroundDataPolicy（Cellular allowed / Wi-Fi only=既定 / Wi-Fi skip Low Data / Off）と合わせて networkAllowed() を返す。通信を伴う背景処理は backgroundAllowed() かつ networkAllowed() で実行する。

CLIP 埋め込みのスマート方針

埋め込みは回線NG時にクラウド写真（サムネDL）をスキップしてローカル写真だけ続行する（unembeddedRefKeys(limit:localOnly:) で DB 側に "L-" 前缀で絞り込み）。ローカルが尽きたら終了し、Wi-Fi/電源の復帰（onChange）で scheduleBackgroundFill() を再起動してクラウド分を拾い直す。

設定

アプリ横断の設定なので、機能別ではなく設定ルートの General → Background & Battery（BackgroundSettingsView）に「Power」「Background Data」を並べて置く。背景 CLIP の速度段階は Albums の Auto Albums 側（処理の重さ）に残す。
