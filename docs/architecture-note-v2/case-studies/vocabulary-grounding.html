事例: 語彙接地アルゴリズムの誕生

「風景」「動物」のような広い言葉を検索可能にする——素直な実装が計測で全滅し、そこからタグ重心 → 凝集した高原 → ゲートつき精錬と、計測に導かれて段階的にアルゴリズムが形になった記録（ADR-101/102/105）。「個別の対応表を書かない」という制約が、結果的に汎用で美しい機構を生んだ。

問題

索引側のシーンタグは Vision の約 1,300 クラス（mountain・beach・sushi…）。ユーザーの言葉は「風景」「食べ物」「動物」。両者は語彙が合わないので、タグ照合は「広すぎるタグ（outdoor）だけ拾い、狭くて確実なタグ（mountain）を取りこぼす」最悪の当たり方をしていた。「風景→山・海・夕日」と対応表を書けば直るが、語彙の数だけ表が要る＝破綻する。ユーザーからの要求も明確だった：「個別対応ではなく汎用的な機能に」。

第 1 案の全滅：語同士（text↔text）の類似

クエリ語と各タグ名を CLIP テキスト塔に通し、テキスト埋め込み同士のコサインで近いタグへ展開する——一見正しい設計は、Caltech-101 の計測で全滅した：接地できた語 3/10・F1 0.300。

なぜ壊れたか（原理） CLIP が学習しているのは「画像と説明文が近くなる」ことだけで、テキスト同士の距離は訓練目標に入っていない。実測すると、テキスト埋め込みは異方性が強く、どの語も語彙全体と 0.67〜0.83 の高い類似で横並びになり、camera のような「ハブ語」がほぼ全クエリの上位に出た。しかも接地を諦めた語は「間違えない」ので Precision は 1.0 に見える——F1 で見なければ、この失敗は成功に化けていた。

転回：タグ重心（text↔image）

問いを変えた。「風景 は mountain という語に近いか」ではなく、「風景 は mountain タグが付いた写真たちに近いか」。各タグについて、そのタグが付いた写真の CLIP 画像埋め込みの平均（＝重心）を作り、クエリ語のテキスト埋め込みと text↔image で比べる——これは CLIP の訓練目標そのものの使い方である。

  • 結果：接地 10/10・F1 0.86（対 0.300）。
  • コスト：画像埋め込みは全写真ぶん既に索引にあるので新規推論ゼロ——51k 件を 1 回舐めて平均するだけ（実測 約 2 分・結果はキャッシュ）。
  • 副産物：タグの意味がそのユーザーのライブラリの写真で定義される（雪山ばかりの人の mountain はそういう意味になる）。

採用規則は絶対閾値を使わない：類似分布からの突出（z ≥ 3）で判定し、上位から標準偏差幅のバンドで採る。実測の z は pizza 6.07 / dog 4.31（正しい接地）に対し landscape 1.68（語彙に相当物なし）——きれいに分離する。

第 2 の壁：「animal 型」の広い語

ところが「動物」は接地できない。該当するタグが多すぎて（数十クラス）、どれも突出しない——山が無い「高原」の分布になる。z しきい値を下げると今度は雑音語（nostalgia・happiness）の高原まで通ってしまう。分布の形だけでは「一貫した高原」と「雑音の高原」を区別できない（MAD などのロバスト統計も試したが animal のスコアはむしろ下がった）。

突破口は意味情報の追加：上位候補たちが画像空間で互いに近いか（凝集度）を測る。animal の上位候補（emu・flamingo・kangaroo…）は互いに近く、雑音語の上位候補はバラバラ——重心どうしの平均コサインを背景分布（全ペアのサンプル）に対する z スコアにすると、animal 2.24 / insect 2.44 vs 雑音語 0.17〜1.11 で完全分離した。こうして「凝集した高原は接地する」規則が生まれ、animal の F1 は 0.746→0.902。しきい値とバンド幅は 9 組のパラメータ掃引で決め、雑音語の門が開かないことを負例テストで固定した。

仕上げ：ゲートつき凝集精錬

バンド選択には端の混入（bird のバンドに紛れた minaret）と裾の取りこぼし（food の strawberry・crab）が残る。そこで選択集合との限界凝集（候補 1 件と集合の平均類似の z）で「混入を刈り・裾を伸ばす」精錬を足した——が、無条件に適用すると乗り物が壊れた（F1 0.40→0.25）。車・飛行機・船は正解どうしが視覚的に似ていない（凝集 z 0.15）ので、凝集を頼る精錬とは相性が最悪なのだ。結論：グループ自体が視覚的に一貫しているとき（z ≥ 1.0）だけ精錬するゲートを付ける。bird 0.833→0.909・food 0.667→0.800、乗り物は無傷。

否定語（「〜が写っていない」）は接地できなければ捨てる——索引に無い概念の「不在」は検証できないため（ADR-100 の証拠主義）。この全規則は seam（ConceptExpander）越しの純ロジックなので、固定ベクトルで完全にテストできる。

一般化できる教訓
  1. 埋め込みは「訓練目標どおり」に使う——CLIP のテキスト同士を比べるのは目的外使用で、異方性に殺される。片側を画像重心に置き換えるだけで別物になる。
  2. Precision 1.0 は「解けている」ことを意味しない——諦めの多い方式ほど混ざらない。F1 で比較しなければ誤採用していた。
  3. 分布の形で足りなければ意味を足す——z スコア（形）で分離できない高原は、候補どうしの距離（意味）が分ける。
  4. 強い規則ほどゲートを付けて出す——精錬は前提（視覚的一貫性）が成り立つ集合にだけ効く。前提を検査してから適用する。
